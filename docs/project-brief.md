# 项目简报：GameAsset Studio

> 状态：M0 规划稿。本文描述**要做什么、不做什么、如何判定 MVP 完成**；不含已实现功能与实验结论。
> 相关文档：[architecture.md](architecture.md) · [experiment-plan.md](experiment-plan.md) · [roadmap.md](roadmap.md)

## 1. 一句话定义

一个运行在单台 Windows + 单卡（RTX 5060 Ti 16GB）工作站上的**游戏概念美术可控生成与评测平台**：用 SDXL + ControlNet 控制构图，用结构化记录保证可复现，用对照实验回答"哪种参数/控制方式更好"。

## 2. 背景

游戏概念美术在"需求 → 成稿"之间通常有大量探索：同一角色或道具需要几十个风格与构图变体。通用文生图工具能快速出图，但在生产语境中有三个缺口：

1. **控制缺口**：文字难以精确指定轮廓、姿态、构图，返工率高。
2. **复现缺口**：一次"好结果"往往伴随未记录的参数、模型版本和随机状态，团队内无法复刻。
3. **判断缺口**：没有实验设计与指标，选型依赖个人偏好，也无法证明"哪个设置更好"。

ControlNet 解决第一点，工程化的运行记录解决第二点，实验与评测解决第三点。本项目将三者串成一条最小但完整的链路，而不是再做一个出图界面。

## 3. 核心问题（研究 / 工程问题）

| 编号 | 问题 | 说明 | 验证方式 |
| --- | --- | --- | --- |
| RQ1 | 在 16GB 单卡上，SDXL 1024² 的可用参数空间与性能边界是什么？ | 步数、CFG、分辨率、采样器如何影响耗时、显存与失败率 | EXP-01 / EXP-02 / EXP-05 |
| RQ2 | Canny 控制强度与终止时机如何影响结构遵循与风格自由度？ | 太强则画面僵硬、太弱则不受控，需要可操作的取值建议 | EXP-03 / EXP-04 |
| RQ3 | 自动指标（边结构一致性、CLIP 相似度）与人工判断的一致性如何？ | 决定自动指标能否用于筛选，还是只能作为辅助 | EXP-04 的人工评分对照 |

RQ1、RQ2 是工程可用性问题；RQ3 是评测方法问题，结论只在小样本范围内成立。

## 4. 目标用户与使用场景

**主要用户**

- 独立游戏团队的概念美术 / 技术美术：给定灰模或线稿，批量探索风格，并保留可复现的候选集。
- 个人美术：把"提示词 + 结构参考 + 固定种子"沉淀为可复用配方。

**次要用户**

- 生成模型工程实践者：关注条件控制、显存 / 延迟特性与实验可复现性，可复用本项目的实验框架。

**典型场景（MVP 内）**

1. 美术上传一张 Canny 边缘图，设置提示词与风格描述，生成 N 张构图一致的变体。
2. 美术调整控制强度，观察结构遵循与风格自由度的变化。
3. 工程师按配置批量跑参数网格，得到带完整记录的产物与汇总表。

**非场景**：多人协作、在线服务、资产入库、实时交互式绘制。

## 5. 范围

### 5.1 In Scope（MVP）

- SDXL 1024² 文生图，参数可配置并完整记录。
- ControlNet Canny 单条件控制。
- 基于 ComfyUI API 的后端调用与任务状态查询。
- 单机单 worker 的串行任务执行。
- 运行记录（manifest）、批量实验执行、基础指标计算与汇总。
- 最小测试与静态检查（不依赖 GPU 的单元测试）。

### 5.2 Out of Scope（当前阶段明确不做）

- 训练 / 微调基础模型、ControlNet、LoRA。
- 多机分布式推理、多用户权限、计费。
- Redis / PostgreSQL / Docker 等基础设施。
- 3D 资产、绑定、动画相关能力。
- 移动端、在线 SaaS 部署。
- 对生成结果做版权或商用合规判定（仅在记录中标注权重许可来源）。

### 5.3 约束

| 类别 | 约束 |
| --- | --- |
| 硬件 | Windows + RTX 5060 Ti 16GB；R7000P 暂不参与 GPU 推理 |
| 引擎 | 阶段一以 ComfyUI 为唯一生成引擎，预训练权重 |
| 依赖 | 不擅自下载权重、不擅自安装大型依赖；权重与产物不入库 |
| 架构 | 单进程后端 + 独立 ComfyUI 进程；文件系统记录，不引入数据库 |
| 时间 | 以里程碑推进，每个里程碑有可验证的退出标准 |

## 6. MVP 定义与验收标准

**MVP 的范围**：M1–M4 完成后，用户能通过 API 提交一次 SDXL 文生图或 Canny 控制生成，得到图像与可复现的 manifest；能批量执行一个 ControlNet 对照实验并导出汇总表。

**验收标准**（逐条可验证，未通过即不算完成）：

| # | 标准 | 判定方式 |
| --- | --- | --- |
| A1 | 提交生成请求返回图像与 manifest | manifest 含模型标识与哈希、全部采样参数、种子、工作流哈希、ComfyUI 版本、耗时、显存峰值 |
| A2 | 可复现 | 使用同一 manifest 与相同环境重跑，输出逐像素一致；若因非确定性算子无法一致，必须记录实测差异并给出明确判定标准（不以"应该一样"代替验证） |
| A3 | Canny 控制有效 | 3 张不同参考图，人工 5 分制结构一致性平均 ≥ 3，且至少 2 张 ≥ 3；同时保留不使用 ControlNet 的对照图 |
| A4 | 批量实验可执行 | 一次配置驱动的批量运行产出汇总表；失败项有错误原因与重试记录，不静默丢弃 |
| A5 | 安全与边界 | 服务仅监听 127.0.0.1；无密钥入日志 / 入库；产物路径限制在运行目录内；仓库无权重文件 |
| A6 | 无 GPU 环境可验证部分逻辑 | 单元测试可在无 GPU 机器运行（ComfyUI 调用使用 mock） |

阈值说明：A3 的"≥ 3 分"是预先声明的验收门槛（5 分制），不是实验结论；评分表与流程见实验计划第 7 节。

**非目标验收**：不要求 UI、不要求并发、不要求跨机器复现（跨机器仅记录环境差异）。

## 7. 成功标准

分三层，避免把"跑通"当成"做好"：

1. **工程可用**：A1–A6 全部满足；一次失败可定位到具体环节（请求 / 工作流 / ComfyUI / 输出）。
2. **流程可复现**：任意一条历史记录可在同一台机器上重建；环境、模型、工作流三者版本齐全。
3. **结论可信**：实验有基线、控制变量、样本量与统计口径；自动指标与人工评分的不一致被显式讨论。

量化指标（**全部待测**，不预设数值）：单图延迟中位数、显存峰值、生成失败率、结构指标（边 IoU）、提示词一致性（CLIP 余弦）、人工评分均值与极差。基线测量完成后再确定"可接受范围"，并把理由写入实验记录。

## 8. 关键假设与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| RTX 5060 Ti（sm_120）与 ComfyUI / PyTorch 版本兼容性未验证 | 可能无法启动推理或需要更换 wheel | M1 第一件事做环境冒烟测试；记录驱动 / CUDA / torch 版本 |
| ComfyUI API 非正式版本化，节点类名与工作流格式可能变化 | 模板失效、复现失败 | 锁定 ComfyUI 版本；启动时校验节点；工作流哈希入 manifest；升级需重跑基线 |
| 16GB 显存对高分辨率 / 多 ControlNet 余量有限 | OOM、需要降级策略 | MVP 限定 1024² 单条件；性能实验记录显存峰值与失败点 |
| 自动指标效度不足（CLIP 分数 != 美术质量） | 结论误导 | 指标定位为筛选辅助；必须配合人工评分与定性分析 |
| 小样本 + 单卡单环境 | 结论不可外推到其他硬件 / 模型 | 明确标注适用范围；报告失败与异常值，不只报均值 |
| 模型权重许可不明 | 结果无法合规分发 | 权重来源与许可证入库记录；不分发权重 |
| 单人项目范围膨胀 | MVP 延期 | 以本文件的 Out of Scope 为准，新需求进入 backlog 而非当期 |
